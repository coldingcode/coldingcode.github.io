设置、凭据与身份：机器状态的三张面孔

设置（settings）是「可热更新的用户配置」，凭据（credentials）是「可替换来源的密钥」，身份（identity）是「匿名但稳定的用户标识」。三者都遵守 AGENTS.md 的一条硬约定：可调参数必须可配置，配置可热更新。

§3机制：三层配置面

  1. settings：命名空间化（如 agentLoop、shell）的键值 + 变更通知。provider 订阅变更事件重读——这就是「改设置即时生效」的通道（与 04 页的补丁热更新互补：settings 是数据热更新，patch 是结构热更新）。
  2. credentials：凭证引用（名字）→ 值 的解析。10 页 adapter 的 API key 按请求解析（不缓存进 config）——所以换 key 不需要重启。
  3. identity：一个机器生成的稳定匿名 id——遥测/统计的归因键，不是登录态。

§5易错点

凭证不进请求 config（10 页的冻结链）：config 会被深冻结、落 request/header 事件（09 页）——若 key 混进去，就等于把密钥写进日志。所以 10 页 adapter 的 key 是 stream 时经 credentials 解析的。

16 页 env 基线的 scrub 与 credentials 的分工：scrubbedParentEnv 剥离宿主环境里的凭证（不给子进程）；credentials 是显式引用的通道（只给申请的 consumer）。两者合起来才是完整的密钥卫生。
