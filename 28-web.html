§3机制：搜索与抓取的分工

  1. 搜索（search）：provider 调搜索 API（DeepSeek 搜索 / Perplexity / Exa），返回结果条目。
  2. 抓取（fetch）：provider 抓取 URL 正文——web-fetch-http 是本地 HTTP 实现。
  3. 消费：tool-web 把两者合成模型可见的工具（web_search/web_fetch），结果经 13/14 页的调度与流水线。

与 15 页 shell 对照读：完全同一套三件套骨架，只是「能力」从执行命令换成了访问网络。读到这里，你已经有能力不看文档猜出任何新 seam 的结构。

§5易错点

搜索 provider 的凭证从哪来？与 llm adapter 一样走 credentials seam（31 页）——provider 不硬编码 key，按请求解析。这保持了「provider 可替换、配置可热更新」。

抓取内容的信任边界：web 内容是外部输入，进入工具结果前要考虑大小截断与编码（类似 16 页的 tail-keep 问题）——超大页面会撑爆上下文。
