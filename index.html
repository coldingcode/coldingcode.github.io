DeepSeek Harness · Code-Level Reading

树状总览：从入口到心脏，再到旁支

这套页面按调用链顺序精读源码：从 apps/cli/src/bin.ts 开始，沿启动链走到 agent loop 的心脏，再从心脏分出「工具执行」和「shell 能力」两个旁支。每一页都聚焦一个函数/一组紧邻的代码，标注文件路径与行号，逐行解释它在做什么、为什么这样写。

图 0阅读树

图 0怎么读这套页面

  1. 沿主干 A 读（00→04）：搞清「从敲下 dsh web 到一棵插件树活起来」的每一行代码。
  2. 沿主干 B 读（05→14）：跟踪一条消息从进队列到工具结果落盘的完整调用链。这是全书重点，10/12/13 是从 09/11 自然长出的分支。
  3. 旁支（15→17）：从工具流水线的通用机制出发，落到一个具体能力（shell）的三件套实现，学会「怎么读一个能力」的模板。
  4. 每页的代码引用都标真实文件路径 + 真实行号，建议把源码窗口放在旁边对照；行号锚定 master @ rc.7。

图 0开读前需要知道的三件事

① 一切皆插件。模型适配器、工具注册表、会话日志、agent loop 本身，全部是插件，全部能从配置替换。不存在特权内核。

② 模型可见 ⟺ 已记录。送进模型请求的内容必须能从 session log 重建——所以模型历史来自 deriveMessages() 对日志的投影，而不是任何内存对象（在 06/09 页你会看到它的行级实现）。

③ waterfall 事件必须调 next() 才委托；serial 事件没有 next()；emit 是纯通知不可否决。这是所有扩展点代码的语法基础（08/10/14 页反复出现）。
