终端与 LSP：subprocess 之上的持久交互

终端（terminal）是「持久会话的交互式 shell」——16 页的 subprocess 有进程树管理，但没有「会话持续」的语义。终端 seam 在它之上加持久层。LSP 是语言服务器协议客户端——让模型读写代码符号而非文本。两者都是 16 页下层 seam 的消费者。

(卷一连接点) 16 页 subprocess（PTY/进程树）· 15 页 seam 模板 → 本域：terminal / terminal-bash / tool-terminal* / lsp / lsp-stdio → (回心脏) 终端的增量输出经 jobs（25 页）或直接进工具结果

§3机制：持久会话与语言服务器

  1. terminal = subprocess + 持久：普通 bash 命令每次 spawn 新进程；终端会话保持一个 PTY 进程跨多次工具调用存活（增量输出、前台进程组）。16 页的 spawnTerminal 与进程树清理就是它的底座。
  2. lsp = 结构化代码访问：LSP 协议让模型做符号级操作（定义跳转、引用、补全），而不是 grep 文本。stdio provider 通过 subprocess spawn 语言服务器进程，走 JSON-RPC。
  3. 两者都站在 16 页的下层上：换 subprocess provider（如 e2b 远程）时，terminal 和 lsp 一起跟着搬——15 页「共享执行世界」结论的第二个例子。

§5易错点

终端会话的存活边界比命令长：17 页的「executor-only 重载后后台进程存活」在终端上更显著——终端会话绑定 subprocess provider，重载 terminal provider 不杀进程（与 16 页同一条边界）。

PTY 的前台进程组检测：16 页提过的 process-inspector（Linux /proc、macOS ps）在 0.1.2-alpha.3 新增了 windows-inspector（325 行）——三平台进程表探测齐全。这是 terminal 正确清理会话树的前提。
