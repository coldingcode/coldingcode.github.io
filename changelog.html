§6同步方法（供后续复用）

每轮 pull 后的标准流程：

  1. git pull --ff-only，记录新 HEAD 与 release 版本。
  2. 圈定影响面：git diff --stat <旧版本tag/commit> HEAD -- <站点锚定的目录>——只有站点引用的文件变更才需要动站点。
  3. 逐文件 diff：对每个有变更的锚定文件 git diff，判断是「行号位移」（只改行号）还是「语义变更」（重写内容）。
  4. 重验证锚点：对站点引用的每个 file:line，用 grep -n/sed -n 核对新位置的符号是否还是原来那个。
  5. 批量更新版本号：sed -i 's/0\.x\.y-rc\.N/新版本/g' *.html。
  6. 语义变更写进对应页 + 本页：凡上游改了行为，对应页的解读必须跟上，并在本页留档。
  7. 校验：残留旧版本号扫描、坏 SVG 属性扫描、内部链接检查。
  8. 提交：站点是独立 git 仓库（coldingcode.github.io），commit + push。
