§1构造器：agent 手里握着什么

70-72

ReactLoopAgent 实现 Agent 接口（03 页的老页面讲过接口，本页的 07 页会讲 Inbox）。它持有三个关键对象：inbox（输入队列投影）、phase（状态机真相）、session（持久日志）。

92

agentEvents(loopCtx, this)：把「这个 agent」融合成事件派发器——此后所有 agent/* 事件的 scope 过滤都以它为 subject。构造一次，热路径不再分配。

93-97

Inbox 的三个通知回调，每个只做一件事：把 inbox 的实时变化转成 live 事件。注意这是「live 通知」，与 inbox 内部的 durable 事件（agent/inbox/spliced，07 页）是两个域——后者进日志，前者不进。

100-101

从投影恢复位置：sessionProjections.stateOf(session, 'turnBoundary') 拿 lastTurn——0.1.2-alpha.3 起不再用 findLast 扫日志，改从「会话投影」注册的 turnBoundary 单元取（loop 自己注册该单元，所以键恒在）。resume 的 agent 仍从持久状态续上编号——投影是日志的索引，真相还在日志。

102

初始 phase：idle，lastTurn 是日志里最后那个 turn。

103-104

两个作用域概念（07 页还会遇到）：scope 是注册边界 + carrier；ctx 是 extend({agent: this}) 后的 agent 作用域上下文——在这个 ctx 上注册的东西随 agent 销毁而撤销，ctx.agent 能拿到自己。

105

RuntimeContextProjection（runtime-context.ts，76 行）：把动态运行时上下文投影成候选 user/message 的持久化快照（08 页 preStep 的第三步用到）。

§2三态 Phase 与 setPhase

39-47

三态各有自己的载荷：running 和 maintenance 都带 abort（可取消）和 wakeRequested（挂起的唤醒请求）；running 还带当前 turn/step 编号。idle 只记住 lastTurn——下个 turn 从它 +1。

108-110

status 是 phase 的派生投影：maintenance 对外报 idle（维护任务不是「在跑 turn」）。

113-120

setPhase 是 phase 的唯一写入口（private）。只在 status 实际变化时发 agent/status——invariant.ts 断言「无 no-op 重复迁移」的依据。

§3kick：最外层循环

219-221

三层循环的最外层：只要 turn() 返回 true 就再来一轮。turn() 返回 false 表示「欠账清了」，返回 true 表示「还有活」。

222-223

driver 边界吞掉一切错误——但注意注释：「已报告的失败和取消在这里被包含」。错误不是被静默吞掉：turn() 里已经通过 throwError 发过 agent/error（§4 会看到），这里的 catch 只是让 driver 能正常收敛。

224-230

收敛逻辑：如果 phase 还在 running（说明 turn 循环因异常跳出），把它收成 idle；若期间有人挂起了唤醒请求且 inbox 有货，重新拉起 driver——这就是 §5 wakeDriver 里 latch 的重放点。

§4turn：开一轮，跑 step，关一轮

264, 268

先落盘，再改内存：turn/start 先 append 进日志，然后才更新 phase.turn。边界一旦开了就永远在日志里——即使下一秒 abort。

269-270

两个循环变量：turnEnds（turn 的结局，null = 尚无结局）和 target（首个 step 从 next-turn 队列 claim）。

273

每轮循环开头都 throwIfAborted()——abort 信号在每步边界检查（后续 294、297 也是）。这是取消语义的落点：取消不打断正在执行的代码，只在边界生效。

275-276

调 preStep（08 页详述）拿 decision。reject → turn 以 blocked 关闭，返回 false 结束 kick 循环。注意：即使 pre-step 被拒，claim 过的消息也已经离开 inbox（08 页会看到 claim 在 preStep 内部）。

283-286

空首步仍关 turn：被移除的唤醒消息或 enter 被改写为空，仍然拥有 turn 边界（turn/start 已落盘），只是不花模型调用、也不产生 step 事件。日志诚实记录「有过这次尝试」。

288-289

step/start 先落盘，phase.step 后更新——与 turn/start 同一纪律。

291-293

逐条 append user/message，带 surfaceOp: 'append'——这是消息进入「模型可见投影」（surface）的方式（06 页详述）。

296

跑真正的 step()（11 页详述）——一次模型调用 + 工具执行。

299

max-tokens 是 sticky 的：一旦某步触顶，后续正常完成的 step 不能把 turn 结局降级成 completed。条件 turnEnds === null || turnEnds.kind !== 'max-tokens' 精确表达这一点。

300-301

finally 里无条件 append step/end——即使 step() 抛出，step 边界也闭合。

304-307

agent/turn-stopping 是 serial 事件（没有 next()）：给策略一次「拦截 turn 关闭」的机会——反对者在这个监听器里 agent.steer(...)，机器随后重读 inbox。看 308：如果 steer 加了货，nextStep 非空，就不 break——数据决定，监听顺序改不了结果。

309

下一轮 target 改为 next-step——后续 step 优先消费转向/注入队列。

311-324

错误路径两分支：abort → turnEnds=aborted 且 rethrow（让 kick 的 catch 收尾）；其他错误 → 结构化失败：LlmError 保留事实，其余压平为 errorChain 文本 + UNKNOWN 码。随后 throwError（203-208 行）先发 agent/error 再 throw——错误通知与传播分离。

325-332

finally 无条件 append turn/end 带 reason。六种 reason：completed / max-tokens / blocked / error / aborted / interrupted（interrupted 是持久化后端专用的 crash 恢复标记，loop 不发出）。

333-338

返回值的语义：inbox 还有货 → 换新 AbortController（旧 latch 作废——活 driver 自己 claim 队列）、清 wakeRequested、step 归零，返回 true 再来一轮；没货 → false，kick 收敛。

§5wakeDriver：谁把 agent 拉起来

182-190

非 idle 分支：latch。不能现在跑，把 wakeRequested 置 true 挂起，等收敛后重放（§3 的 220 行）。两个例外不挂起：disposed（要销毁了，不等人）和「活 driver 自己会 claim 队列」。maintenance 与 aborted 的 driver 无法送达唤醒，必须 latch。

201-202

activityDone 是「整个 agent 活动的静默哨兵」——whenIdle() 就是等它。每次起 driver 都换新的 promise。

194-197

直接 setPhase 到 running：turn 从 lastTurn 起步（turn() 里 +1），step 归零，新 AbortController——这个 controller 就是本轮可取消的边界。

201-202

withInitiator：AsyncLocalStorage 的进程本地因果归因——「这个 turn 是谁发起的」。它是归因不是授权，跨进程/持久化失效。kick 的完成驱动 driver.resolve，失败驱动 driver.reject。
